# 선행 사전 대비 수정 내역 (lexicon v2)

대상 파일: `config/lexicon_ko.yaml` (사전), `scripts/claims.py` (사전을 읽어 문장을 코딩하는 코드), `scripts/tests/test_claims.py` (회귀 테스트).

선행 사전은 TextMining-med-claim-trace 프로젝트의 `config/lexicon_ko.yaml`이다. 그 사전은 기사와 논문을 1:1로 맞추고 표현 강도를 0~6점으로 매기는 설계에 맞춰져 있었다. 이번 프로젝트는 논문 초록(한국어 번역), 기사 본문, 기사 제목 세 집단에 같은 사전을 적용해 비율을 비교하므로 그대로 쓸 수 없어 고쳤다.

이 사전과 코드가 내는 값은 사람이 검증하기 전의 자동 코딩이다. 정밀도와 재현율은 아직 재지 않았다 (5절).

## 1. 범주 틀의 출처

**관계 표현의 강도 (RQ1).** 선행 사전은 Sumner et al. 2014 (BMJ)의 7범주를 한국어로 옮긴 것이었다. v2는 Adams et al. 2017 (J Exp Psychol Appl)이 보인 3단계 구분에 맞춰 7범주를 직접 인과 / 가능성 / 연관으로 묶고, 관계 없음을 명시한 경우를 무관으로 따로 두었다.

| 선행 사전 (Sumner 7범주, 선행 사전의 주석 기준) | v2 |
|---|---|
| 6 단정적 인과 (`causal`) | `direct` 직접 인과 |
| 5 인과 가능 (`causal` + 뒤의 '수 있') | `possible` 가능성 |
| 4 조건부 인과 (`conditional`: 가능성, 우려, 의심, 수도 있, 지도 모르) | `possible` 가능성 |
| 3 모호 (`ambiguous`) | 항목별로 나눔 (2절) |
| 3 약한 모호 (`ambiguous_weak`) | 삭제 |
| 2 상관 (`correlational`) | `association` 연관 |
| 1 관계 없음 명시 (`no_relationship`) | `none` 무관 |
| 0 진술 없음 | 값 없음 (`strength: None`) |

확인이 필요한 점: 한국어 표현 하나하나를 Adams et al.의 세 단계 가운데 어디에 둘지는 이 작업에서 원문과 대조하지 않았다. 특히 '수도 있다'·'지도 모른다'류와 '수 있다'류를 같은 `possible`에 둔 것, `possible`을 `association`보다 강하다고 본 순서는 보고서에 인용하기 전에 원문으로 확인해야 한다.

**조건 표현 (RQ2).** 조건 범주에 쓸 한국어 선행 사전을 찾지 못했다. 그래서 EBM-NLP (Nye et al. 2018)와 CONSORT의 범주를 틀로 삼아 대상(population) / 용량(dose) / 기간(duration) / 설계(design) / 한계(limitation) 5범주로 정했다. 범주 안의 한국어 표현 목록은 선행 사전의 것을 고쳐 쓴 것이고, 두 출처에서 가져온 것이 아니다.

## 2. 수정 내역

변경 종류: 추가 / 삭제 / 이동 / 규칙 변경(사전 항목은 그대로이고 코드의 처리 방식이 바뀜).

### 2.1 주장 문장 필터

| 범주 | 항목 | 변경 | 이유 |
|---|---|---|---|
| 필터 | 약물명 **또는** 결과명 **또는** 복용어(`exposure`) 중 하나 | 규칙 변경 | 약물 단서 **그리고** 그 묶음의 부작용 단서가 같은 문장에 있을 때만 주장 문장으로 센다. 하나만 있어도 통과시키면 "췌장염은 췌장에 염증이 생기는 질환이다" 같은 설명문이 주장으로 잡힌다. |
| 필터 | 제목은 필터를 끔 | 규칙 변경 | 제목도 본문 문장과 똑같이 필터를 거친다. 세 집단에 같은 기준을 적용해야 비율을 비교할 수 있다. |
| `exposure` | 복용, 투약, 투여, 사용, 처방 등 | 삭제 | 필터에 쓰지 않는다. 약물명이 없는 문장을 통과시키는 통로였다. |
| `drug_terms` | 위고비, 세마글루타이드/세마글루티드, Wegovy, semaglutide, 오젬픽, Ozempic, 리벨서스, Rybelsus | 추가 | 선행 사전은 약물명을 묶음 설정에서 받았다. 이번에는 사전에 고정했다. |
| `drug_terms_broad` | GLP-1, 비만치료제, 비만약, 당뇨약, 다이어트 약·주사 | 추가 | 일반어다. 기본 필터에서는 쓰지 않고 민감도 분석(`broad_drug=True`)에서만 쓴다. |
| `outcome_terms` | 묶음 4개의 정규식 | 추가 | `scripts/label_articles.py`의 `TOPIC`과 같은 패턴이다. 묶음 판정과 주장 필터가 어긋나지 않게 했다 (테스트가 두 값이 같은지 확인한다). |
| `outcome_terms_broad` | NAION: 시신경, 실명, 시력 상실 | 추가 | 기사는 NAION을 '실명'으로 풀어 쓰는 일이 많다. 다만 다른 눈 질환도 걸리므로 기본 필터에서는 쓰지 않는다 (`broad_outcome=True`). |

### 2.2 관계 표현의 강도 (`claim_strength`)

| 범주 | 항목 | 변경 | 이유 |
|---|---|---|---|
| 전체 | 6개 하위 목록 → `direct` / `possible` / `association` / `none` | 이동 | 1절의 틀. |
| `ambiguous_weak` | 위험, 부작용, 발생, n배 | 삭제 | 이 낱말만 있어도 '모호한 인과'로 잡혀 "위고비 부작용 사례가 보고됐다"가 주장이 됐다. 관계를 말하는 표현이 아니다. |
| `ambiguous` → `association` | 연결(돼/된/됐/고리), 관계가 있/보/맺 | 이동 | 방향 없이 이어져 있다는 말이다 (영어 'linked to'의 번역어). 맨몸의 '연결'은 뺐다. |
| `ambiguous` → `direct` | 영향을 미치다/주다/끼치다 | 이동 | 약물이 결과에 작용한다는 뜻의 서술이라 연관이 아니라 인과다. 방향이 불분명하다는 점은 이번 틀(방향을 따지지 않음)에서 문제가 되지 않는다. 명사 '영향'만 있는 경우('영향 평가')는 뺐다. |
| `ambiguous` → `possible` | 위험 신호 (+ 안전성 신호, 이상 신호) | 이동 | 약물감시에서 '신호'는 확인되지 않은 가능성을 뜻한다. |
| `ambiguous` | 적신호, 빨간불, 경고등 | 삭제 | 관계의 성격을 말하지 않는 수사 표현이다. 강도 범주를 줄 근거가 없어 값 없음으로 둔다. |
| `ambiguous` → `association` | 위험/발병률/발생률 + 증가·상승·↑ (명사구) | 이동 | '위험 증가와 관련이 있었다'의 명사구. |
| `ambiguous_weak` → `association` | 위험 + n배 ('위험 2배') | 이동 | 맨몸의 'n배'는 삭제했고, 위험 명사에 붙은 형태만 남겼다. |
| `direct` | 높이다, 늘리다, 키우다, 증가·상승·악화시키다, 낮추다, 줄이다, 감소시키다 | 규칙 변경 | 위험·발생률·가능성 또는 부작용 명사가 목적어일 때만 잡는다 (`{RISKP}`, `{EVENT}` 매크로). 그러지 않으면 "체중을 15% 줄이는 위고비"가 직접 인과가 된다. |
| `direct` | 유발, 일으키다, 초래, 야기 | 규칙 변경 | 목적어가 부작용·병명·위험 명사이거나 바로 앞이 약물일 때만 잡는다. "복통을 유발하는 췌장염", "실명을 유발하는 시신경 질환"(질환 설명), "유발할 위험"(위험 명사를 꾸밈)은 뺀다. |
| `direct` | 촉발, 부추기다, 불러일으키다 | 추가 | 기사에 나오는 인과 동사. |
| `direct` | 때문, 탓 | 규칙 변경 | 약물·복용 표현 바로 뒤에 올 때만 잡는다. "췌장염 위험 때문에 처방하지 않는다"는 약물이 원인이라는 말이 아니다. |
| `direct` | (약물)(으)로 인한 | 추가 | "세마글루타이드로 인한 급성 췌장염". |
| `direct` | 원인 | 규칙 변경 | '원인이다/원인으로/원인일'처럼 서술하는 형태만. '원인을 조사했다'는 뺀다. |
| `direct` | 높아진다, 커진다, 증가한다 (현재·미래형 자동사) | 규칙 변경 | 위험 명사가 주어일 때만. 과거형은 `association`으로 옮겼다 (아래). |
| `direct` | 생긴다/걸린다/나타난다/발생한다/겪는다, (으)로 이어진다, 실명·자살·자해 + 한다/할 수 있다, 시력을 잃다 | 추가·규칙 변경 | "췌장염이 발생할 수 있다", "실명할 수 있다"처럼 부작용이 서술어인 문장을 잡는다. 부작용 명사가 주어일 때만, 그리고 '걸릴 위험'처럼 위험 명사를 꾸미는 경우는 뺀다. 과거형 사건 보고("췌장염이 발생했다")는 잡지 않는다. |
| `direct` | 예방, 막다 | 삭제 | "심혈관 질환을 예방하는 다른 신약"처럼 부작용과 무관한 문맥에서 잡혔다. 위험을 낮춘다는 주장은 '위험을 낮추다/줄이다'로 잡힌다. |
| `causal` → `association` | 높아졌다, 커졌다, 증가했다, 늘었다 (과거형 자동사) | 이동 | 과거형은 관찰한 결과를 서술한다. 위험·부작용 명사가 주어일 때만 잡는다 ("사용량이 폭발적으로 증가했다"는 뺀다). |
| `possible` | 시사한다/시사하는, 것으로 보인다/보였다, 추정된다, 듯, 것 같다, 의혹 | 추가 | 번역된 초록의 학술체. |
| `possible` | 위험이 있다, 위험성을 제기 | 추가 | "자살 충동을 겪을 위험이 있다는 연구결과". '위험이 있는 환자'는 뺀다. |
| `possible` | 의심 | 규칙 변경 | '의심 사례', '췌장염이 의심되면'은 진단상의 의심이므로 뺀다. |
| `no_relationship` → `possible` | 인과관계는 불분명/회의적 | 이동 | 관계가 없다는 말이 아니라 모른다는 말이다. '인과관계는 입증되지 않았다/증명하지 못했다'도 여기에 넣었다. |
| `association` | 관찰 | 규칙 변경 | '관찰되었다/관찰됐다'만. 맨몸의 '관찰'은 '관찰연구'(설계)에서 잡혔다. |
| `association` | 것으로 나타났다, 높게 나타났다, 높음을, 보고됐다/보고된 바 | 추가 | 번역된 초록과 기사의 관찰 서술. '보고됐다'를 연관으로 본 것은 판단이다 (3절). |
| `association` | 위험이 높다/크다/낮다 (현재형 비교) | 추가 | "확률이 4배 이상 높다". '가능성이 높다'(그럴 법하다)는 `possible`이므로, 가능성·확률은 비교 대상이나 숫자가 붙을 때만 연관으로 본다. |
| `association` | 상관, 연계 | 규칙 변경·삭제 | '상관'은 '상관관계/상관성'만 ('상관없이' 때문). '연계'는 '병원과 연계'처럼 관계 표현이 아닌 쓰임이 많아 삭제. |
| `none` | 상관없, 무관 | 규칙 변경 | '상관없이', '무관하게'(= 관계없이 적용된다는 뜻)는 뺀다. |
| `none` | 높지/많지/크지 않, 증가하지 않, 연관성을 발견하지 못, 인과성 못 찾, 우려와 달리, 사실무근, 위험 안 높여 | 추가 | 긍정 단서가 따로 잡히지 않는 부정 형태들. |

### 2.3 부정·양태 규칙 (`negation`, `modal_after`, `frame_cues`, `argument_cues`, `indirect_question`, `inquiry_after`)

| 범주 | 항목 | 변경 | 이유 |
|---|---|---|---|
| 부정 | `negation_after` (단서 뒤 8글자) | 규칙 변경 | 범위를 '단서 끝부터 그 절의 끝까지'로 넓혔다. 절 경계는 쉼표, 말줄임표, '지만/는데/으나/며/면서' 등이다 (`negation.clause_boundary`). |
| 부정 | `negation.after_cue` | 규칙 변경 | 단서 바로 뒤(같은 어절 + 다음 어절 하나)의 부정. 글자 수가 아니라 어절로 센다. "때문에 처방하지 않는다"의 부정이 '때문'에 붙지 않게 하려는 것이다. |
| 부정 | `negation.before_cue` | 추가 | '안 높여'처럼 앞에 오는 짧은 부정. |
| 부정 | `negation.clause_final` | 추가 | 절 끝 부정: '~다는 근거는 없다', '~것으로 보이지(는) 않는다', '발견/확인/관찰되지 않았다', '~지 않음', '~는 것은 아니다', '볼 수 없다', '오명을 벗다' 등. 단서가 이 범위 안이면 `none`. |
| 부정 | `negation.non_assertion` | 추가 | 단정 유보: '단정할 수 없다', '입증되지 않았다', '불분명', '근거가 부족' 등. `none`이 아니라 `possible`로 본다 (3절). |
| 양태 | `modal_after.can` / `.may` (단서 뒤 8글자) | 규칙 변경 | 한 정규식으로 합치고 범위를 절 끝까지로 넓혔다. "유발하거나 악화시킬 수 있다"처럼 '수 있'이 떨어져 있어도 `possible`로 낮춘다. |
| 틀 | `frame_cues` | 추가 | '~것으로 나타났다', '~을 시사한다'는 앞의 명제를 감싼다. 같은 절의 앞선 단서가 `none`이면 이 단서도 `none`. "위험을 증가시키지 않음을 시사한다"가 `possible`이 되지 않게 한다. |
| 논항 | `argument_cues` | 추가 | '위험 증가', '위험 2배' 명사구는 뒤따르는 서술어가 `none`이면 `none`. "위험 증가와 연관되지 않았다". |
| 간접 의문 | `indirect_question` | 추가 | '높이는지 평가하였다', '유발 여부'는 주장이 아니므로 세지 않는다. 뒤에 '불분명하다'류가 오면 `possible`. |
| 탐구 서술 | `inquiry_after` | 추가 | '연관성을 분석했다', '가능성을 조사하기 위해'도 세지 않는다. 초록의 목적 문장에 흔해서, 그대로 두면 초록 쪽 연관·가능성 비율이 부풀려진다. |
| 물음표 | 문장 안에 '?'가 있으면 표시 | 규칙 변경 | 문장이 물음표로 끝날 때만 `question: True`. 강도는 그대로 계산한다. |
| 우선순위 | 가장 강한 긍정 주장 | 규칙 변경 | 부정·조정 규칙을 먼저 적용하고 direct > possible > association > none 순으로 가장 강한 것을 쓴다. |

### 2.4 조건 표현 (`conditions`)

| 범주 | 항목 | 변경 | 이유 |
|---|---|---|---|
| 전체 | 8범주 → 5범주 | 이동 | `animal`, `sample_size`, `effect_size`는 `extra_conditions`로 옮겼고 기본 집계에서 뺐다 (`include_extra=True`로 볼 수 있다). |
| `population` | 환자, 당뇨, 비만, 과체중, 성인, 참가자, 대상자 | 삭제 | 위고비 기사라면 거의 모두 나오는 낱말이라 조건을 전했는지를 가르지 못한다. |
| `population` | 비당뇨, 당뇨병이 없는, 제1·2형 당뇨, 병력·과거력·기저질환, 고위험군, 가임기, 노년, 한국인·아시아인 등 | 추가 | 대상을 좁히는 한정 표현. '제2형 당뇨병 치료제'(약의 적응증 소개)는 뺀다. |
| `population` | n세 | 규칙 변경 | '2세대'가 잡히지 않게 했다. |
| `dose` | 복용량 | 삭제 | '용량' 항목에 이미 포함된다. |
| `duration` | 장기 | 규칙 변경 | '장기간, 장기적, 장기 복용/투여/사용/추적…'만. 臟器('장기 손상')와 구분되지 않았다. |
| `duration` | 단기, 누적, 추적 | 규칙 변경 | 같은 방식으로 기간 뜻이 분명한 형태만 ('단기간', '누적 용량', '추적 관찰'). |
| `design` | RCT, 위약, 이중 맹검, 환자-대조군 연구, 부작용 보고 시스템·FAERS, 약물감시, 실제 임상 자료 | 추가 | 이 주제의 논문에 나오는 설계. |
| `limitation` | (변경 없음) | — | 선행 사전 그대로. |

### 2.5 hedge / booster

| 범주 | 항목 | 변경 | 이유 |
|---|---|---|---|
| 겹침 | booster가 hedge 안에서 잡힘 ('불확실'의 '확실', '입증되지 않았다'의 '입증') | 규칙 변경 | 사전 목록은 두고 코드에서 푼다. booster 일치가 hedge 일치와 겹치거나, 앞 글자가 '불'이거나, 바로 뒤에 부정이 오면 booster에서 빼고 hedge로 센다. |
| `booster_negation` | window 8, 부정 패턴 | 추가 | 지시받은 값은 6글자였다. 6이면 "입증하는 것은 아니다"(부정이 7번째 글자에서 시작)를 놓쳐서 8로 두었다. 부정이 이 범위 안에서 시작하면 hedge로 본다. |
| `boosters` | 분명 | 규칙 변경 | '성분명'의 '분명'을 뺐다. "위고비(성분명 세마글루타이드)" 때문에 기사마다 booster가 잡혔다. |
| `hedges` | 시사한다, 것으로 보였다 | 추가 | `possible`에 넣은 학술체와 맞췄다. |

### 2.6 가져오지 않은 부분

`direction`(위험 증가/감소 방향), `sensational`, `advice`, `attribution`, `comment_reactions`, `stopwords`는 이번 연구 질문에 쓰지 않아 가져오지 않았다. 영어 초록용 코더(`EnglishClaimCoder`)와 리드 구간 나누기(`segment_article`)도 가져오지 않았다. 문장 분리와 잡음 문장 제거(`split_sentences`, `is_noise_sentence`)는 그대로 옮겼다.

## 3. 판단이 필요했던 결정

1. **"단정할 수 없다"는 `possible`.** 관계를 부정하는 말이 아니라 판단을 미루는 말이다. `none`으로 세면 '무관하다'는 주장이 실제보다 많아진다. '입증되지 않았다', '불분명하다', '근거가 부족하다'도 같다. 반대로 '발견되지 않았다', '확인되지 않았다', '근거는 없다'는 결과가 없었다는 보고이므로 `none`이다. 기준을 바꾸려면 `negation.non_assertion`의 항목을 `negation.clause_final`로 옮기면 된다.
2. **'영향을 미친다'는 `direct`, '연결'은 `association`, '위험 신호'는 `possible`, '적신호·빨간불·경고등'은 삭제** (2.2).
3. **'보고됐다'는 `association`.** "위고비 투여 후 췌장염 사례가 보고됐다"는 약물과 부작용이 함께 나타났다는 관찰이다. 사례 보고를 주장으로 세지 않으려면 `association`과 `frame_cues`에서 '보고' 항목을 지우면 된다.
4. **'~을 부작용으로 판단/지목/추가'는 잡지 않는다.** `ambiguous_weak`의 '부작용'을 삭제하라는 방침을 따랐다. "EMA가 NAION을 세마글루타이드의 매우 드문 부작용으로 판단했다" 같은 문장은 주장 문장이지만 강도 값이 없다. 규제기관의 판단을 인과 주장으로 볼지는 팀이 정해야 한다.
5. **`negated`의 뜻.** 부정 규칙이 단서를 `none`으로 바꿨을 때만 True다. 사전의 `none` 항목에 바로 일치한 경우("관련이 없다")는 False다. 무관 주장인지는 `strength == 'none'`으로 본다.
6. **강도 단서가 없는 주장 문장은 `strength: None`.** `none`(무관)과 다르다. 문서 요약에서는 `n_uncoded_claim_sentences`로 따로 센다.
7. **`possible` + `association`이 한 문장에 있으면 `possible`.** 정해진 순서(direct > possible > association > none)를 따른 결과다. "연관될 가능성이 있다"가 "연관이 있었다"보다 위에 놓인다는 점은 해석할 때 주의해야 한다.

## 4. 개발 중 점검

규칙을 고치면서 `scripts/raw_news/`에 있던 기사 본문 89건(2026-11-23 기준, 중복 전재 포함)에 돌려 보았다. 사람이 코딩한 정답과 비교한 것이 아니고, 이 89건을 보면서 규칙을 고쳤으므로 독립된 검증도 아니다. 사전이 의도대로 움직이는지 본 것이다.

| 항목 | 값 |
|---|---|
| 문장 수 / 주장 문장 수 (기본 필터, 묶음 구분 없이) | 1,875 / 236 |
| 주장 문장의 강도 | direct 22, possible 40, association 64, none 11, 값 없음 99 |
| 제목 89개 중 주장 문장 | 기본 필터 12개, `broad_outcome` 22개, `broad_outcome`+`broad_drug` 31개 |

읽을 때 주의할 점 두 가지.

- 주장 문장의 약 42%(99/236)는 강도 값이 없다. 대부분 사건 보고("37명에게서 NAION이 발병했다"), 규제 조치, 수치 나열이다.
- 기본 필터에서는 제목의 13%(12/89)만 주장 문장이다. 제목은 약물명이나 병명을 생략하는 일이 많다 ("살 빼려다 실명 위기?"). 제목 집단의 비율은 적은 수로 계산된다.

## 5. 알려진 한계

**검증되지 않았다.** 사람 코딩과의 일치도를 재지 않았다. 번역된 초록에는 아직 돌려 보지 못했다 (작업 시점에 번역본이 없었다). 초록의 학술체 표현은 예문으로만 확인했다.

**못 잡는 부정.**
- 이중 부정: "위험을 높이지 않는 것은 아니다" → `none`으로 나온다.
- 말줄임표·쉼표 건너의 부정: "췌장염 유발한다더니…근거 없어" → 앞 절의 '유발'은 부정되지 않아 `direct`가 남는다. 제목에 흔한 형태다.
- 단서에서 두 어절 넘게 떨어진, 목록에 없는 부정 서술어: "유발한다는 주장은 틀렸다", "우려할 필요 없다".
- 조건절·가정: "유발한다면", "높이는 것으로 확인되면"은 주장으로 센다.

**단서가 누구의, 무엇에 대한 말인지 확인하지 않는다.**
- 인용과 주장을 구분하지 않는다. "…유발한다고 주장했다", 따옴표 안의 발언, 다른 연구를 소개하는 문장도 글쓴이의 주장처럼 센다.
- 주어가 약물인지 확인하지 않는다. "NAION은 시력 상실을 초래할 수 있다"(질환이 주어)도 잡힌다.
- 단서가 그 묶음의 부작용에 대한 것인지 확인하지 않는다. 한 문장에 부작용이 여럿이면("저혈당 위험이 낮고 췌장염은…") 다른 결과에 대한 서술이 그 묶음의 값이 된다. `bundle=None`으로 돌리면 어느 부작용에 대한 주장인지도 알 수 없다.
- 방향(위험 증가/감소)을 구분하지 않는다. "자살 위험을 낮췄다"도 `direct`다.

**필터가 놓치는 문장.**
- 대용어: "이 약은 췌장염을 유발할 수 있다"는 약물명이 없어 주장 문장이 아니다. 약물과 부작용이 이웃한 두 문장에 나뉘어 있어도 놓친다.
- 초록은 약물을 'GLP-1 수용체 작용제'로 부르는 일이 많은데 기본 필터의 약물 목록에는 없다 (`broad_drug`에만 있다). 집단마다 필터 통과율이 다를 수 있다.
- NAION을 '실명'·'시신경 손상'으로만 쓴 문장은 기본 필터를 통과하지 못한다 (`broad_outcome`에만 있다).

**목록의 한계.**
- hedge의 '수 있'은 능력·허용("처방받을 수 있다")과 가능성을 구분하지 못한다. 점검한 기사에서 hedge 일치의 절반 이상이 '수 있'이었다.
- booster의 '반드시'는 대부분 권고 문맥("반드시 의사와 상담")에서 잡혔다. 주장의 확실성을 높이는 표현이 아니다.
- `association`의 과거형 비교 서술('높았다', '많았다')은 주어를 확인하지 않는다. "체중 감소 효과가 높았다"도 잡힐 수 있다.
- 문장 분리는 kiwipiepy가 있으면 그것을 쓰고 없으면 정규식을 쓴다. 두 방식의 결과가 다를 수 있으므로 한 분석 안에서는 한 방식만 써야 한다. 8글자 미만 문장은 잡음으로 보고 버린다.
- 단서 위치(`start`, `end`)는 정규화한 문장(HTML 엔티티 풀기, NFKC) 기준이다. 원문 위치와 다를 수 있다.
